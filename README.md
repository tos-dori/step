# Step! — Local

로그인 없이 바로 열고, 지금 할 일 하나를 시작하고, 멈췄다가 이어가는 실행 보조 앱.

제목·메모만으로 할 일을 추가한다. 묶음은 자유롭게 열고 닫고 정리한다. 제목을 누르면 편집하고 재생 버튼을 누르면 현재 작업이 된다. 시작·끝 기준, 준비, 종류, Step 수는 필요할 때 설정한다.

작은 행동의 체크는 선택 사항이고 다시 눌러 되돌릴 수 있다. `이번 Step 마침`은 실행 단위의 마침이다. 마지막 Step 이후에도 `2/2`와 실제 체크 상태가 남는다. 별도의 `완료`를 눌러야 할 일 자체가 완료된다. 단순 중단은 Step을 추가하지 않고 체크·메모·타이머 경과를 보존한다.

## 실행

빌드와 서버 계정이 필요 없는 정적 앱이다. 개발 미리보기:

```sh
python3 -m http.server 4173
```

브라우저에서 `http://localhost:4173`을 연다. 실사용은 고정된 HTTPS 주소로 제공한다. `file://` 저장 동작은 브라우저마다 달라 실사용 기준으로 삼지 않는다.

## 저장과 이전

- Firebase, 로그인, 계정 동기화, 외부 런타임 의존성 없음.
- 새 저장 키: `step_local_v1:state`. 복구본도 같은 전용 접두사만 사용한다.
- 원래 Step의 `step_live_v1`이나 복구 키를 읽거나 쓰지 않는다.
- 계정이나 기기 사이 자동 동기화는 없다. `백업·복구`에서 JSON을 내보내고 가져온다.
- 기존 Step의 `STEP_BACKUP_V1` 백업을 명시적으로 가져올 수 있다. 기존 ID·메모·체크·완료 상태를 보존한다. 같은 ID를 병합할 때 기존 작업을 덮어쓰지 않는다.
- 주요 변경 직전 최대 8개 복구본을 남긴다. 저장·복구본 쓰기가 실패하면 변경을 반영하지 않는다. 깨진 데이터를 빈 목록으로 덮어쓰지 않는다.
- 다른 탭의 최신 저장을 발견하면 덮어쓰기를 차단하고 백업 후 다시 불러오도록 안내한다.

## 검증

```sh
npm install
npm test
npx playwright install chromium
# 별도 터미널에서 위의 HTTP 서버를 실행한 뒤
npm run test:browser
```

모델·백업·실패 주입 테스트와 모바일 390×844 / 데스크톱 1440×1000 브라우저 흐름 테스트를 분리했다. 테스트 통과와 실제 배포 사이트 검수는 별개다. 실제 확인 범위는 `VERIFICATION.md`를 참고한다.

## 배포

목표 저장소는 `tos-dori/step-local`. GitHub Pages의 Source를 GitHub Actions로 설정한 뒤 main에 반영하면 배포 워크플로가 실행된다. 원래 `tos-dori/step`에서는 배포 작업이 실행되지 않도록 저장소·브랜치를 함께 제한했다.

## 구현 기준

`tos-dori/step`의 보존 원본 `08a1949b1d6c4636dd0d6ff4d18f66c6fc89fed7`과 UI 개편 `281a0650402743f48eccdf108c6f7a361e1e2cbd`를 참고했다. 원본의 실행 기준·체크 메모·중단과 보관 기능을 독립 로컬 앱의 화면에 연결하고, 기존 화면을 숨겨놓고 새 UI를 덧씌우던 구조는 사용하지 않는다.
