# Step! v6 — 배포와 데이터 계약 (2026-10-12)

## URL과 소스
- 대표 주소: https://tos-dori.github.io/step/ → `app/v6/` (v6 실사용 화면).
- 구버전 실행 파일: `legacy/index.html` (원본 정적 리소스에 연결).
- 변경 전 main 전체: `archive/pre-v6-main-2026-10-12` (HEAD `281a0650402743f48eccdf108c6f7a361e1e2cbd`).
- v6 파일: `app/v6/index.html`, `app/v6/app.js`, `app/v6/style.css`.
- 과거 Step JS/CSS/Firebase 모듈과 기존 task/piece 데이터는 삭제하지 않았다.

## 동기화 — 반드시 알고 있어야 할 점
- localStorage는 각 기기에서 분리된다. 세 기기 공유에는 **동일한 Firebase 이메일 계정으로 로그인**해야 한다.
- 기존 Step의 owner-only Firestore 규칙을 그대로 사용한다. 새 인증 방식이나 공개 쓰기 권한을 추가하지 않는다.
- v6 로컬 상태: `step_v6_live_v1`. 이전 `step_live_v1`은 수정하지 않는다.
- 클라우드: 기존 `stepUsers/{uid}/states/main` (schema-3 revision/hash 트랜잭션)를 사용하되 기존 `state.tasks`는 그대로 두고 `state.workspaceV6` 필드를 추가한다.
- v6가 처음 나타나면 기존 클라우드 tasks를 읽어 v6로 변환한다. 클라우드가 비어 있으면 해당 브라우저의 기존 `step_live_v1`도 확인한다. 다른 내용이 양쪽에 있으면 자동으로 합치거나 덮어쓰지 않고 사용자에게 선택을 요청한다.
- v6 변경 시 이전 서버 main을 기존 50칸 history ring에 저장한다. v6 로컬 상태는 12개 checkpoint slot과 JSON 파일 내보내기를 제공한다.
- 다른 기기에서 같은 상태를 동시에 바꾸면, 자동 덮어쓰기 대신 충돌 화면을 제공한다. 오프라인 변경은 로컬에 저장하고 연결 복귀 시 재시도한다.
- **주의:** 기존 버전을 이미 열어둔 기기나 오래된 PWA 캐시에서 v6 모르는 클라이언트가 서버를 수정하면 `workspaceV6` 필드가 제거될 수 있다. v6는 제거를 감지한 기기의 로컬 내용을 자동 폐기하지 않지만, 이전 앱은 v6를 읽지 못한다. 세 기기 모두 새 대표 URL에서 시작하도록 한다.
- 기존 클라우드의 구버전 tasks는 v6와 별도로 보존하며, v6가 새로 만든 할 일은 구버전 화면과 역동기화되지 않는다. 이전 앱은 복구·참조용이다.

## 실사용 제약
- 이 작업은 HTML 프로토타입을 *그대로 복사*하는 작업이 아니라 v6 정보구조를 실제 상태 저장/동기화에 연결한 재구현이다.
- iPhone/iPad Safari의 standalone, safe area, 16px 입력, 키보드 높이, 오버스크롤 경계를 고려한다. 브라우저 자동 검증이 실제 iOS 터치·키보드 시험을 대체하지 않는다.
- 기기 간 동기화의 정상 여부는 첫 로그인 후 **각 기기에서 같은 목록 확인 → 한 기기 변경 → 다른 두 기기에 반영** 과정을 거쳐 확정한다.
- 과거 로컬 데이터를 포함한 기존 사용자 데이터는 삭제·초기화하지 않는다. 실제 사용자 기기의 Firebase 로그인 여부와 오래된 PWA 캐시는 원격에서 자동 검증할 수 없다.
